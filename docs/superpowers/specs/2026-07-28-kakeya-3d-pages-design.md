# Simon Synapse 掛谷猜想 3D 三頁體驗設計

## 1. 目標

在 Simon Synapse 主網站內新增一組「掛谷猜想 3D 實驗室」，以 3 個獨立網址分別提供互動科普、沉浸藝術與數學教學體驗。三頁共用同一套 3D 幾何與控制核心，但保有明確不同的內容密度、互動方式與視覺節奏。

本功能需符合以下結果：

1. 使用者能在桌機、平板與手機上開啟並操作 3D 場景。
2. 3 個頁面可直接互相切換，且保留 Simon Synapse 的品牌辨識與返回網站的路徑。
3. 數學敘述正確區分「有限取樣示意」與「掛谷集合的嚴格定義及證明」。
4. 不需要帳號、後端、資料庫、使用者追蹤或外部即時資料。
5. 不更動首頁目前固定的核心作品排列。

## 2. 資訊架構

### 2.1 正式路由

| 路由 | 頁面名稱 | 主要任務 |
| --- | --- | --- |
| `/kakeya/interactive/` | 互動科普 | 讓使用者直接操控 3D 線段與取樣參數 |
| `/kakeya/immersive/` | 沉浸藝術 | 用全螢幕光影與動態呈現方向壓縮的視覺感受 |
| `/kakeya/learn/` | 數學教學 | 逐步解釋定義、直覺、維度與三維結果 |

每頁頂端提供相同的 3 模式切換器，使用正常連結而非僅靠 JavaScript 切換，確保網址可分享、瀏覽器上一頁可用，並在 JavaScript 失效時仍能導覽。

### 2.2 既有網站入口

在既有「作品案例」集合新增「掛谷猜想 3D 實驗室」作品資料，使 `/projects/` 可發現此功能。作品的主要開啟連結指向 `/kakeya/interactive/`，作品說明頁則交代 3 種體驗與數學資訊來源。首頁固定核心作品名單維持不變。

## 3. 數學內容邊界

### 3.1 必須傳達的內容

1. 掛谷集合在 `R^n` 中包含每一個方向的一條單位線段。
2. 掛谷猜想主張任何這類集合都具有完整的 Hausdorff 維度 `n`；相關版本也考慮 Minkowski 維度。
3. Hong Wang 與 Joshua Zahl 於 2025 年的工作證明三維掛谷集合具有 Minkowski 與 Hausdorff 維度 3。
4. 網頁只會呈現有限數量、具有可見半徑的線段或管線，因此不能視為零測度集合、無限方向集合或證明本身。

### 3.2 禁止誤導的呈現

1. 不將線段數、畫面覆蓋率或管線包圍盒稱為 Hausdorff 維度。
2. 不顯示看似精確但缺乏數學意義的「猜想完成百分比」。
3. 若顯示估算覆蓋量，必須標示為有限取樣的視覺指標。
4. 不宣稱互動場景重現 Besicovitch 集合或 Wang–Zahl 證明。

主要數學來源：

- Hong Wang、Joshua Zahl，〈Volume estimates for unions of convex sets, and the Kakeya set conjecture in three dimensions〉，arXiv:2502.17655。

## 4. 共用架構

### 4.1 Astro 整合

沿用現有 Astro 專案與 `BaseLayout.astro`。新增一個掛谷專用版面元件，負責：

- Simon Synapse 頁首、頁尾與 SEO metadata。
- 3 模式切換器與目前頁面標示。
- 3D 畫布容器、載入狀態、錯誤訊息與文字替代內容。
- 掛谷頁面共用的色彩變數與響應式版面。

各頁保持獨立 Astro 路由，不以 iframe 或獨立子網域載入。

### 4.2 共用 3D 核心

採用由專案打包的 Three.js 模組，不使用 CDN。共用核心分為以下邊界：

1. `direction sampling`：以可重現的球面取樣產生方向向量；相同參數必須得到相同結果。
2. `segment placement`：將固定長度線段放入有限區域，位置演算法與視覺材質分離。
3. `scene controller`：建立攝影機、繪圖器、尺寸更新、指標裝置控制與生命週期清理。
4. `mode presets`：定義 interactive、immersive、learn 的相機、色彩、線段數量、動畫速度與互動權限。
5. `status adapter`：把載入、暫停、WebGL 不可用與參數狀態轉成可讀文字。

3D 場景會使用單一幾何資料與批次繪製策略，避免每條線段建立大量獨立 DOM 或繪圖物件。畫布只在可見且允許動態效果時持續更新；頁面隱藏或使用者暫停後停止動畫迴圈。

### 4.3 資料流

```text
頁面預設值或使用者控制
        ↓
模式設定與參數驗證
        ↓
方向取樣 → 線段配置 → Three.js 幾何緩衝區
        ↓
場景控制器 → Canvas 畫面
        ↓
文字狀態與有限取樣指標
```

不保存個人資料。若保留使用者的「減少動態效果」或上次參數，只能儲存在目前裝置，且不得作為分析或追蹤資料。

## 5. 三頁體驗

### 5.1 互動科普頁

首屏以可立即操作的 3D 場景為主，旁邊或下方放置精簡說明。

控制項：

- 拖曳旋轉、滾輪或雙指縮放。
- 播放／暫停方向變化。
- 線段數量：提供效能安全範圍內的離散級距。
- 管線半徑：改變可視粗細，並提示這是 `δ-tube` 的視覺近似。
- 分散程度：調整線段中心位置的聚合程度。
- 重設場景。

顯示資訊限於取樣方向數、線段長度、管線半徑與動畫狀態，不把這些數字描述為證明結果。

### 5.2 沉浸藝術頁

首屏採接近全螢幕畫布，文字只保留頁名、短句、模式切換器、播放狀態與必要操作提示。

視覺方向：

- 延續 Simon Synapse 的深藍、青色、紫色與洋紅色。
- 線束使用亮度、透明度與景深感表現層次，不使用外部圖片。
- 攝影機以緩慢軌道運動呈現不同方向；使用者互動後暫停自動運鏡，避免控制權衝突。
- 不自動播放聲音，本期也不加入音訊功能。

當系統偏好 `prefers-reduced-motion: reduce` 時，預設停止自動運鏡、粒子漂移與連續脈動，只保留手動旋轉及靜態構圖。

### 5.3 數學教學頁

採分段敘事，每段搭配同一畫布的狀態切換：

1. 一條單位線段。
2. 平面內逐步增加方向。
3. 將方向擴展到球面。
4. 把線段中心收攏，展示「小體積直覺」與交疊。
5. 區分 Lebesgue 測度、Hausdorff 維度與 Minkowski 維度。
6. 說明三維結果與有限示意的限制。

步驟可由上一頁／下一頁按鈕、鍵盤與觸控操作。每個步驟都有文字標題、簡短解釋和目前步驟狀態，不依賴顏色辨識。

## 6. 視覺與響應式規則

1. 桌機採畫布與內容雙欄；窄螢幕改為畫布在上、控制與文字在下。
2. 互動目標至少維持現有網站的觸控尺寸規範。
3. 畫布必須有明確邊界、鍵盤焦點樣式與操作說明。
4. 主要文字維持可選取的 HTML，不把說明文字繪製進 Canvas。
5. 色彩對比、焦點、縮放與文字換行延續既有 Simon Synapse 規範。
6. 頁面載入時先顯示標題、說明與靜態替代圖形，3D 程式完成後再增強為可互動畫布，避免空白首屏。

## 7. 錯誤與降級處理

### 7.1 WebGL 不可用

顯示清楚的狀態卡：

- `Status`：此裝置無法啟動 3D 圖形。
- `Root Cause`：瀏覽器、顯示卡或設定未提供必要的 WebGL 能力。
- `Suggested Fix`：改用最新版瀏覽器、開啟硬體加速，或閱讀下方文字與靜態示意。

數學教學文字、頁面切換與來源連結必須保持可用。

### 7.2 效能不足或內容不可見

- 偵測長時間低幀率後降低線段數量與像素密度，不顯示恐嚇式錯誤。
- 畫布離開視窗或分頁隱藏時停止動畫。
- 失去 WebGL context 時嘗試一次安全重建；失敗後切換為靜態狀態卡。

## 8. SEO、來源與網站治理

1. 三頁各自有繁體中文 title、description、canonical URL 與社群分享資訊。
2. 教學頁以原始論文為主要來源，作品說明頁列出相同來源。
3. 頁面明示「3D 圖像是有限取樣示意，不是數學證明」。
4. 不在新頁面放置廣告，以免干擾全螢幕互動與教學步驟。
5. sitemap 必須包含 3 個新路由。

## 9. 驗證策略

### 9.1 單元測試

- 方向向量長度接近 1。
- 固定種子與參數產生可重現結果。
- 線段長度固定且參數上下限有效。
- 模式預設值與減少動態效果邏輯正確。
- 失去 context、頁面隱藏與銷毀時會停止動畫並釋放事件監聽。

### 9.2 路由與內容測試

- 3 個網址建置後均存在。
- 每頁 title、H1、canonical URL 與模式切換器正確。
- 教學頁包含 Wang–Zahl 來源、三維結果及示意限制說明。
- `/projects/` 可發現掛谷猜想作品入口，但首頁核心作品數量與順序不變。

### 9.3 瀏覽器與無障礙測試

- Chromium 桌機與行動版尺寸可完成旋轉、縮放、按鈕與滑桿操作。
- 僅用鍵盤可以切換頁面、操作教學步驟並控制播放狀態。
- `prefers-reduced-motion: reduce` 時不會自動運鏡。
- WebGL 不可用時顯示降級內容，頁面仍可閱讀與導覽。
- 執行既有 Astro check、單元測試、建置驗證與 Playwright 無障礙測試，避免破壞現有路由。

## 10. 完成條件

1. 3 個路由在正式建置中產生並可直接開啟。
2. 3 頁共用核心但呈現出明確不同的用途與體驗。
3. 桌機、觸控、鍵盤及減少動態效果皆有可用流程。
4. 數學敘述、來源及「有限示意」邊界通過內容測試。
5. 既有 Simon Synapse 檢查、測試與建置全部通過。
6. 發布後，正式網址回傳成功並能從 `/projects/` 找到入口。

## 11. 本期不做

- 不建立帳號、留言、社群或排行榜。
- 不加入聲音、VR、AR 或多人同步。
- 不嘗試以數值模擬估算 Hausdorff 維度。
- 不建立 3 個子網域或獨立部署專案。
- 不重新設計 Simon Synapse 首頁與既有核心作品排序。
