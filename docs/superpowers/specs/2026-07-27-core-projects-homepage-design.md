# Simon Synapse 首頁固定核心作品設計

## 目標

首頁「作品實證」固定顯示下列 4 個核心作品，順序不得受發布日期、更新日期或其他新作品影響：

1. 小賽 AI 樂透預測
2. Matt Pocock Skills 中文手冊
3. 2026 世界盃 AI 預測
4. 小賽影片壓縮器

## 現況

首頁目前先依日期排序所有可見作品，再取前 3 筆。這會讓首頁內容隨新增作品或修改日期而改變，也無法同時呈現指定的 4 個核心作品。

## 核准設計

首頁以固定 Slug 清單選取作品：

```text
xiaosai-ai-lottery
matt-pocock-skills-guide
fifa-ai-prediction
ssa-compressor
```

選取結果依清單順序呈現。作品仍須通過既有公開條件；草稿不會因為列入核心清單而繞過正式站的內容閘門。

本次正式發布時，以上 4 個已核准作品案例會由草稿改為公開，使正式首頁能實際顯示卡片並連往案例頁與外部作品。

## 呈現與導流

1. 沿用既有 `ProjectCard`，不新增卡片變體。
2. 沿用既有響應式 `card-grid`，維持大字、鍵盤操作與行動裝置閱讀體驗。
3. 每張卡片保留兩條明確路徑：
   - 「閱讀案例」前往 Simon Synapse 站內案例頁。
   - 「開啟作品」前往對應的實際作品網站。
4. 「瀏覽全部作品」仍前往 `/projects`，不改變作品總覽的排序與內容。

## 錯誤與內容保護

若固定清單中的 Slug 不存在，首頁不得靜默少顯示作品。自動化測試必須檢查 4 個 Slug、顯示順序及對應外部網址，讓內容搬移或誤刪能在發布前失敗。

## 測試策略

1. 先新增首頁端對端測試，要求「作品實證」區塊正好顯示 4 張卡片，並依核准順序排列。
2. 驗證每張卡片的外部作品網址正確。
3. 先執行測試並確認因現有 3 筆日期排序邏輯而失敗。
4. 實作固定核心作品選取後重新執行測試。
5. 執行型別檢查、單元測試、建置及正式站 HTTP 驗證。

## 不在本次範圍

- 不重新設計卡片外觀。
- 不將外部網站嵌入 iframe。
- 不合併各作品的程式碼、資料或登入狀態。
- 不變更文章區塊、導覽列或作品總覽頁排序。
- 不新增或移除其他作品案例。

## 替代方案與取捨

1. `featured: true`：適合人工挑選，但仍需另外維護排序欄位，無法直接保證指定順序。
2. 新增 `coreOrder` 欄位：擴充性較高，但本次只有固定 4 筆，需修改內容 Schema，超出必要範圍。
3. 固定 Slug 清單：變更最小、順序明確、容易測試，因此採用。
