寫提示詞最容易卡住的地方，往往不是不知道要問什麼，而是腦中的想法還沒有整理成能交代、能驗收的工作。這張圖把我常用的思考過程拆成 9 個步驟：先把想法攤開，再反覆追問、規劃、潤飾，最後留下能交給下一次對話使用的交接內容。

## 這張圖要怎麼用

不必每次都走完 9 步。簡單的問題可以從「提示詞架構師」直接開始；內容複雜、需求模糊時，先做深度訪談與步驟規劃，會比一開始就叫 AI 給答案可靠得多。完成後，再用個人語調與去除制式痕跡的步驟，把結果改成真正像自己會說的話。

Claude Code 的官方文件把 Skills 定義為可重複使用的知識或工作流程，可由使用者直接呼叫，也能在適當情境載入。本頁的 9 個名稱不是 Claude Code 官方固定清單，而是我依個人工作方式整理的範本；你可以依自己的工具、習慣與工作需求增減步驟。

## 最後留下可接手的結果

我最在意的不是這一次提示詞寫得多漂亮，而是下一次能不能快速接著做。因此流程的最後兩步，是把有效方法封裝成可重複使用的 Skill，並留下交接文件。當想法、上下文、目標和語調都保留下來，下一個對話才不必從零開始。
